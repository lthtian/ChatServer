# 第一阶段：容器、轨道、编码包与时间戳

## 1. 容器、编码、流、包与帧

```text
MP4 文件 → 解封装 → H.264 编码包 → 解码 → 像素帧 → 转换并按时间显示
```

| 概念 | 作用 | FFmpeg 对应 |
|---|---|---|
| 容器 | 组织音视频轨道、时间信息和索引，例如 MP4 | AVFormatContext |
| 编码 | 规定媒体数据怎样压缩和恢复，例如 H.264 | AVStream::codecpar 中的 codec_id |
| 流 | 一条逻辑媒体轨道，例如视频轨、音频轨 | AVStream |
| 编码包 | 属于某条流的编码数据及时间戳，不是 TCP 包 | AVPacket |
| 解码帧 | 恢复后的图像或一组音频采样 | AVFrame |

解封装取出编码数据，解码恢复像素或采样。`av_read_frame()` 返回 AVPacket，不能把它当作图片显示；一次送入包也不保证立即得到一帧。

```text
AVFormatContext：整个输入的工作上下文
    ├─ iformat → AVInputFormat：选中的解封装器描述
    └─ streams[i] → AVStream：第 i 条轨道的描述
                       └─ codecpar → AVCodecParameters：该轨道的编码参数

AVPacket：本次读出的编码数据
    └─ stream_index → 对应 streams[stream_index]
```

### 流的归属与包的提取

视频流和音频流是两条逻辑轨道，可以存放在同一个文件中。一条流对应多个包；`AVStream` 保存轨道描述，不会预先把整条流的所有包装入内存。

```text
调用 av_read_frame(input, packet)
    ↓ FFmpeg 内部
解析容器信息，确定数据所属轨道，提取编码数据
填写 packet->data、size、stream_index、pts、dts 等字段
    ↓ 函数成功返回
调用方拿到已经标明归属的包
根据 stream_index 查找流参数，或交给对应流的解码器
```

“解封装器已经知道包属于哪条流”指函数成功返回时，归属识别已经完成。归属来自容器提供的轨道标识或索引，不需要先解码出图像或声音再猜类型。以 MP4 为例，轨道索引描述各轨道数据的位置，解封装器可以据此提取数据。

逐包接口适合从同一输入持续取得音视频数据，调用方再按流处理。即使上层提供“只取视频包”的接口，内部仍需处理遇到的其他流数据。音视频包可以交错返回；返回顺序也不必等于文件中的物理字节顺序，解封装器可能按容器索引跳转读取。

## 2. 输入上下文与轨道参数

以下列出查看器涉及的结构体成员。AVFormatContext 保存本次输入的状态，AVInputFormat 描述解封装器实现，AVStream 描述轨道，AVCodecParameters 保存编码参数。

### AVFormatContext：整个输入

`input` 是管理 `AVFormatContext` 的智能指针。

| 成员 | 类型 | 含义 |
|---|---|---|
| `iformat` | `const AVInputFormat*` | 当前选用的输入格式／解封装器的公共描述 |
| `nb_streams` | `unsigned int` | 已知流数量，即 `streams` 数组元素数；样本为 1 |
| `streams` | `AVStream**` | 流指针数组，`streams[i]` 指向第 i 条流的描述对象 |
| `duration` | `int64_t` | 整个输入的时长，以 `1/AV_TIME_BASE` 秒为单位；可能未知或由估算得到 |
| `bit_rate` | `int64_t` | 整个输入的平均总码率，单位 bit/s；0 表示未知 |

样本 `bit_rate=898726`，约 899 kbps。码率的单位是比特每秒，包大小的单位是字节。

### AVInputFormat：选中的解封装器描述

| 成员 | 类型 | 含义 |
|---|---|---|
| `name` | `const char*` | 解封装器注册时定义的简短名称列表，多个名称以逗号分隔 |

样本的 `iformat->name` 是 `mov,mp4,m4a,3gp,3g2,mj2`。这组相关容器共享大量解析逻辑，由同一个解封装器处理；名称列表不是从当前文件读出的“该文件同时包含哪些格式”。分别打开 MOV 和 MP4 文件，也可能打印相同列表。

| 名称 | 含义 |
|---|---|
| `mov` | Apple QuickTime 的 MOV 容器 |
| `mp4` | MP4 容器，可承载音视频等轨道 |
| `m4a` | 通常用于 MP4 音频文件的名称／扩展名 |
| `3gp` | 面向移动通信多媒体的 3GPP 文件格式 |
| `3g2` | 类似 3GP 的 3GPP2 文件格式 |
| `mj2` | Motion JPEG 2000 文件格式，存放 JPEG 2000 图像序列 |

这里描述的是解封装器；具体 H.264、AAC 等编码由相应解码器处理。文件的容器格式影响解封装器选择，文件自身的时长与轨道信息则保存在 `AVFormatContext`、`AVStream` 中。

### AVStream：一条轨道的描述

| 成员 | 类型 | 含义 |
|---|---|---|
| `index` | `int` | 该流在 `input->streams` 数组中的索引 |
| `codecpar` | `AVCodecParameters*` | 指向该流的编码与音视频参数 |
| `time_base` | `AVRational` | 此流的时间戳单位，按秒表示 |
| `avg_frame_rate` | `AVRational` | 视频平均帧率，可能未知或由探测得到 |

编号 0 不保证是视频流，媒体类型由 `codecpar->codec_type` 判断。变帧率视频的平均帧率不表示所有相邻帧的时间间隔相同。

### AVCodecParameters 与 AVChannelLayout：编码和音视频参数

| 成员 | 类型 | 含义 |
|---|---|---|
| `codec_type` | `AVMediaType` 枚举 | 视频、音频、字幕等大类，如 `AVMEDIA_TYPE_VIDEO` |
| `codec_id` | `AVCodecID` 枚举 | 具体编码，如 `AV_CODEC_ID_H264`、`AV_CODEC_ID_AAC` |
| `width`、`height` | `int` | 视频图像宽高，单位像素；样本为 1820 × 1030 |
| `sample_rate` | `int` | 音频采样率，单位 Hz，按每个声道计算 |
| `ch_layout` | `AVChannelLayout` | 音频声道布局及数量 |
| `ch_layout.nb_channels` | `int` | 布局中的声道数，如单声道 1、双声道 2 |

例如采样率 48000 表示每个声道每秒 48000 个采样。视频字段和音频字段按 `codec_type` 分别读取。

`av_get_media_type_string(codec_type)` 将媒体类型转换为 `video`、`audio` 等字符串，未知时可能返回空指针，所以代码用 `unknown` 兜底。`avcodec_get_name(codec_id)` 返回具体编码名称，例如 `h264`。

## 3. AVPacket：编码数据与包的描述信息

| 成员 | 类型 | 含义 |
|---|---|---|
| `data` | `uint8_t*` | 指向本包的编码数据，不是已经恢复的像素 |
| `size` | `int` | 编码数据的有效长度，单位字节 |
| `stream_index` | `int` | 所属流索引，对应 `input->streams[stream_index]` |
| `pts` | `int64_t` | 呈现时间戳，以所属流的 `time_base` 为单位 |
| `dts` | `int64_t` | 解码时间戳，单位同上 |
| `duration` | `int64_t` | 本包对应内容在呈现时间线上的持续时长，单位同上；0 表示未知 |
| `flags` | `int` | 按位组合的标志，如关键帧、损坏等 |

`pts`、`dts` 为 `AV_NOPTS_VALUE` 时表示未知，不能直接乘时间基。`flags & AV_PKT_FLAG_KEY` 非零表示含关键帧的标记，不能据此完整区分 I/P/B。包时长不是 CPU 解码耗时。

### 程序自定义的输出

| 名称 | 含义 |
|---|---|
| 循环变量 `index` | 遍历流数组的下标 |
| `packet_count`／输出 `packet index` | 本次程序累计的读包序号，不是显示帧编号 |
| `has_audio`／输出 `audio present` | 遍历时是否发现音频流 |
| `pts_s`、`dts_s`、`duration_s` | 程序换算后的秒数，不是结构体里额外保存的字段 |
| 输出 `key` | 检查包标志位后生成的 yes/no |

## 4. 时间单位、时间戳与媒体时间线

### AVRational 与 AV_TIME_BASE

`AVRational` 是分数类型：`int num` 为分子，`int den` 为分母；`av_q2d()` 将它换算为浮点数。具体单位由使用它的字段决定。

| 用法 | 含义与样本 |
|---|---|
| `AV_TIME_BASE` | FFmpeg 固定宏常量 `1000000`，不会随视频文件改变 |
| `AVRational{1, AV_TIME_BASE}` | 每个整数单位代表百万分之一秒，即 1 微秒 |
| `stream->time_base` | 流时间戳每个整数单位代表多少秒，样本为 `1/16384` |
| `stream->avg_frame_rate` | 每秒平均呈现多少帧，样本为 `8/1`，即 8 fps |

不能把所有时间都除以 `AV_TIME_BASE`。样本容器 `duration=5000000` 表示 5 秒；包的 `duration=2048` 则按流时间基换算为 0.125 秒。

### DTS、PTS、帧率与码率

| 概念 | 含义 |
|---|---|
| DTS | 媒体解码时间线上的位置 |
| PTS | 媒体呈现时间线上的位置 |
| time_base | 时间戳每个整数单位代表多少秒 |
| 帧率 | 每秒呈现多少帧，不等于时间基 |
| 码率 | 每秒多少媒体比特，描述数据量 |

AVPacket 的 `dts`、`pts` 是具体的整数字段，与 `data` 指向的编码数据分开。MP4 可以把时间信息存放在容器的表中，由解封装器解释并填入这些字段，不必在每份编码数据前直接存两个时间戳。

`av_read_frame()` 返回包的时间戳以所属流的 `time_base` 为单位：秒数 = 时间戳 × `av_q2d(stream->time_base)`。换算前检查 `AV_NOPTS_VALUE`，它表示时间戳未知。正常顺序读取同一视频流时，DTS 通常按解码时间顺序排列，PTS 可以不递增；不同流的时间基可能不同，不能直接比较原始整数。

### 零点与负 DTS

时间基规定单位，不规定零点。零点由媒体时间线的约定及编码、封装映射决定，不是打开文件的时刻或电脑当前时间。首幅画面的 PTS 常设为 0，但不是所有文件都如此。

如果呈现从 0 开始，解码与重排的准备可以安排在这个零点之前，于是 DTS 为负。它表示媒体时间坐标，不表示程序在启动前运行，也不表示负耗时。播放器会先准备数据，再建立实际播放时钟。

DTS 不要求 CPU 严格按对应间隔解码，解码可以快于播放；`PTS - DTS` 也不是该帧的 CPU 解码耗时。

### 样本中的时间换算

`D:\test_video.mp4`：MP4 容器，只有一条 H.264 视频流，无音轨；1820 × 1030，8 fps，5 秒，共 40 帧。像素格式为 yuv444p，整体平均码率约 899 kbps。

```text
time_base = 1/16384 秒
PTS = 8192      → 0.5 秒
duration = 2048 → 0.125 秒

前五个包的 PTS：0、0.5、0.25、0.125、0.375 秒
前五个包的 DTS：-0.25、-0.125、0、0.125、0.25 秒
解码后前五帧显示顺序：0、0.125、0.25、0.375、0.5 秒
```

本样本第二个包的 `dts=-2048`、`pts=8192`，对应解码时间 -0.125 秒、显示时间 0.5 秒。它提前被读取是为了满足解码依赖，不意味着应当提前显示。

## 5. I/P/B 帧、预测与残差

三者描述的是编码方式，成功解码后都能得到完整画面。I 帧仍是压缩数据，需要解码及必要参数，不是可直接显示的像素数组。

| 类型 | 预测依据 |
|---|---|
| I 帧 | 利用当前图像内已经重建的邻近区域，不依赖其他图像进行帧间预测 |
| P 帧 | 帧间预测块从选定的已解码参考图像取得预测；不同块可选择不同参考图像 |
| B 帧 | 帧间预测块可使用一份预测，也可组合两份预测；参考图像可以位于显示时间的前后 |

P/B 中也可以包含帧内编码的块。参考对象不一定是紧邻的上一帧，也不是所有 P/B 都固定对照同一张 I 帧。GOP 是一组图像的组织结构，影响压缩、跳转和起播；I 帧与安全随机访问入口不能完全画等号。

### 预测与残差

帧间编码通常按块处理，而不是只列出同一坐标上哪些像素发生了变化。物体向右移动时，编码器可在参考图像中寻找相似区域，用它预测当前位置的块：寻找参考位置称为运动估计，按参考位置生成预测称为运动补偿。

预测仍可能不准，因此还需编码残差：

```text
当前真实像素：101   98  100  102
预测像素：    100  100  100  100
残差：          1   -2    0    2

残差 = 真实像素 - 预测像素
重建像素 = 预测像素 + 恢复的残差
```

码流表达预测方式、所需参考与运动信息，以及经过压缩的残差。残差通常经过变换、量化和熵编码，有损量化使重建画面可能与原图不同。B 帧的双向预测可将两份预测组合后再计算残差，并不要求每个块都同时参考前后两张图像。

## 6. 解码顺序、输出顺序与显示时机

假设 P2 参考 I0，B1 同时参考 I0 和 P2，下标表示显示编号：

```text
显示顺序：I0 → B1 → P2
解码顺序：I0 → P2 → B1
```

B1 显示得早，却需要先取得 P2 的像素。“未来参考帧”指显示时间在后，处理 B1 时它已经解码并保存在缓冲中。

对于正常的 MP4/H.264 顺序读取，`av_read_frame()` 已按各流的解码顺序提供包，不需要手动按 DTS 或 PTS 排序。音视频包可以交错返回，根据 `stream_index` 分别交给对应解码器。把编码包按 PTS 排序可能让依赖者先于参考图像进入解码器。

```text
av_read_frame → avcodec_send_packet → 解码器管理参考图像与输出重排
             → avcodec_receive_frame → 播放器按帧时间戳和播放时钟安排显示
```

解码器依据码流中的图像顺序信息重排输出，不只是对 PTS 做排序。解码完成、输出给调用方、实际显示是三个不同环节。输出帧不一定对应刚送入的包，应使用输出帧自身的时间信息。

## 7. 解封装 API 的职责与调用关系

| API | 操作对象与职责 |
|---|---|
| `avformat_open_input(&input, ...)` | 打开输入、识别容器并读取头部；可以创建 AVFormatContext，也可使用预先分配的上下文 |
| `avformat_find_stream_info(input, ...)` | 探测并补齐同一输入上下文中的流信息 |
| `av_read_frame(input, packet)` | 读取一个包并填入 AVPacket；返回 0 表示成功，EOF 表示输入结束，其他负值表示错误 |
| `av_packet_alloc()` | 分配可反复接收数据的包对象，不预先装入整条流 |
| `av_packet_unref(packet)` | 释放本次包数据引用并重置字段，保留包对象供下次使用 |
| `av_packet_free(&packet)` | 释放包数据引用和包对象 |
| `avformat_close_input(&input)` | 关闭输入，释放输入上下文及其持有的流描述等资源 |

```text
avformat_open_input → avformat_find_stream_info
    → 查看 input->streams[i] 的轨道描述
    → 循环 av_read_frame
        → 用 packet->stream_index 找到所属流
        → 按该流 time_base 解释包时间戳
        → av_packet_unref，继续读下一个包
    → 释放包对象，关闭输入
```

### 打开与探测的区别

`avformat_open_input()` 打开输入、识别容器并读取头部，将已有信息填入上下文。成功后即可访问上下文并调用 `av_read_frame()`。

`avformat_find_stream_info()` 读取部分包，必要时尝试解码，尽量补齐头部没有给出的编码参数、采样参数或帧率等信息。返回值表示成功或失败，探测结果写入同一个上下文及关联的流对象。

探测不是读包接口的强制前置条件：头信息完整的文件可能直接读包也能满足需求；其他输入即使能读到包，所需的描述信息仍可能不完整。查看器需要展示流信息，因此保留探测步骤；探测成功也不保证所有字段都已知。

默认探测流程可能提前读包并缓存数据，后续 `av_read_frame()` 会处理这些缓存，不需要应用自行把文件位置回退。没有音轨是合法输入，不能据此判定文件损坏。

## 8. 自定义删除器与资源归属

```cpp
const auto close_input = [](AVFormatContext* ctx) {
  avformat_close_input(&ctx);
};
std::unique_ptr<AVFormatContext, decltype(close_input)> input(raw_input,
                                                           close_input);
```

`unique_ptr` 的第二个模板参数是删除器的类型，构造函数的第二个实参是删除器对象。Lambda 是带调用运算符的对象，`decltype(close_input)` 取得其类型。智能指针销毁且持有非空指针时，调用保存的删除器，通过 FFmpeg 的关闭接口释放输入。

`input.get()` 借出原始指针，不转移所有权。`AVStream` 和 `codecpar` 随输入上下文释放；代码不单独删除它们。`AVPacket` 由程序另外申请，`av_packet_unref()` 释放本次数据引用，`av_packet_free()` 释放包对象。
