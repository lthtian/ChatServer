# 图片客户端：交互细节与失败处理

实现位置：`E:\chat_server_qt\ChatClient\chat_client_electron`。

| 用户看到的场景 | 客户端处理 |
| --- | --- |
| 打开聊天记录 | 一次取 50 条元数据；接近可视区域时加载缩略图。先预留宽高，图片到达时不会把消息挤来挤去。 |
| 点击图片或“查看原图” | 打开预览，先保留缩略图，再下载原图。有服务端确认的字节数才显示百分比。 |
| 下载达到 100% | 进入解码阶段；图片能被浏览器解码后才替换占位图。收到全部字节不等于能正常显示。 |
| 缩略图失败 | 保留消息和尺寸占位；可以重试缩略图，也可以独立尝试原图。 |
| 原图失败 | 预览中保留缩略图和错误原因；重试会重新申请访问票据。关闭预览取消尚未完成的请求。 |
| 快速切换联系人 | 取消旧缩略图请求；历史和图片回调检查当前请求身份，避免把上一会话的结果显示到当前会话。 |
| 查看较早消息 | 使用消息 ID 游标；向前插入历史时补偿滚动位置。收到消息时只有接近底部才自动滚到底部。 |
| 图片发送到 100% | 显示“服务端处理中”，之后是“正在确认发送结果”；收到落库确认才显示为正常图片消息。 |
| 发送超时或断线 | 本地保留文件副本、会话和固定的 client_msg_id。重新登录后显示待继续任务，点击重试。 |
| 确认包丢失 | 重新查询资源，再用同一个 client_msg_id 发布；服务端返回已存在的消息，不追加第二条。 |
| 取消与成功交叉发生 | 服务端已提交消息时不能取消；客户端核实结果并显示已发送，避免错误声称撤回成功。 |
| 切换账号 | 等待旧任务暂停，清理旧页面和资源句柄；任务及缓存按服务地址、账号分别存放。 |

## 资源限制

- 图片：静态 JPEG / PNG，20 MiB，2400 万像素，单边不超过 16000 像素。文件选择过滤只改善体验，C++ 核心和服务端仍独立检查实际内容。
- 发送：最多 20 个待处理任务、2 个并发任务；先复制到应用私有目录，再计算摘要和缩略图。外部原文件移动或删除不影响重试。
- 下载：最多 3 个并发任务；缓存上限 256 MiB，按访问时间回收。原图校验 SHA-256，临时下载文件在失败/取消时删除。
- 服务端：16 个 HTTP 连接、2 个活跃上传；1 个磁盘/解码工作线程，避免两张大图同时解码占满小内存机器。传输每次使用 64 KiB 缓冲。
- 未发布文件：过期或取消后回收；进程崩溃留下的暂存目录超过 24 小时回收。已发布的历史图片不因上传任务过期被删除。

## 代码阅读入口

- `src/image_view.js`：缩略图、原图、解码失败、取消和过期回调。
- `src/image_client.js`：发送状态、原文件副本、原子写入任务记录、恢复与缓存。
- `src/image_transfer.js`：流式上传/下载、字节限制、超时、取消；不跟随重定向。
- `src/desktop_bridge.js` / `preload.js`：主进程持有网络和文件，页面只有明确的业务接口。
- 服务端 `src/server/media_service.cpp`：临时票据、流式 HTTP、工作线程与状态推进。
- 服务端 `src/server/db/media_repository.cpp`：会话授权、事务提交和幂等性。

## 联调运行

无域名和证书时，通过 SSH 同时转发聊天和图片端口。在 Electron 目录中：

```powershell
npm run tunnel
```

输入 SSH 登录密码并保持该终端运行。另开终端：

```powershell
npm run dev
```

客户端使用 `127.0.0.1:16000`；图片票据使用 `127.0.0.1:16001`。服务器仍在 6000 提供聊天，图片 HTTP 只绑定 `127.0.0.1:6002`。本地 HTTP 字节进入 SSH 隧道后加密，不需要开放图片公网端口。

WSL 独立联调可通过 `CHAT_HOST`、`CHAT_PORT` 指向隔离测试服务。原图/缩略图只允许 HTTPS 或回环 HTTP。

`resources/native/chat_image.exe` 和 `opencv_world4130.dll` 是运行依赖，现已复制到当前工作目录。这两个二进制被仓库原有规则忽略，换机器或打包时需从构建产物复制。核心源码和构建方法见 `media/README.md`。
